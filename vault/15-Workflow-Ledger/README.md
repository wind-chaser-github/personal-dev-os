# Workflow Ledger

This is where personal working methods accumulate.

The goal is not to store notes. The goal is to improve how future work is done.

## Promotion Pipeline

```text
Observation -> Candidate -> Trial -> Standard -> Adapter
```

## Levels

### Observation

A thing noticed during real work.

Example: "Bug fixes often miss the failing input shape."

### Candidate

A possible workflow rule worth trying.

Example: "For bug fixes, capture one failing input/output example before editing."

### Trial

A rule used in 2-3 real tasks.

Track whether it reduced mistakes or slowed work too much.

### Standard

A rule accepted into the personal workflow.

Move it into `10-Workflows`, `20-Checklists`, or `30-Patterns`.

### Adapter

A rule that agents should execute automatically.

Promote it into Codex skill, Cursor rule, Claude rule, opencode rule, or a script.

## Rule

Do not promote a rule just because it sounds good. Promote it because it helped on real work.
